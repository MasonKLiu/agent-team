# RFC-001: AI-Native Engineering Governance & Architecture Standards

> 本檔依 RFC-001 原文內容整理。若你手上有原文，可直接覆蓋本檔正文，但請保留最後的「Enforcement map」章節並同步更新。

- **Status:** Enforced
- **Scope:** All teams, autonomous coding agents, CI/CD pipelines
- **Objective:** Keep the revert rate below 0.5% while eliminating line-by-line human code review.

## 0. Keywords

Keywords follow RFC 2119.

- **MUST / MUST NOT**: blocks CI. No exceptions.
- **SHOULD / SHOULD NOT**: deviations require quantitative justification in the PR artifacts.

## 1. Feedback loops

### 1.1 No prompt patching

Teams MUST NOT rely solely on `AGENTS.md`, `.cursorrules` or system prompts to fix recurring agent mistakes. Every manual correction MUST be codified into a deterministic static check (custom ESLint rule, TypeScript constraint, AST check, or architectural fitness test).

### 1.2 Self-healing error messages

Every lint or boundary error MUST include:

1. **Rule ID**
2. **Root Cause**
3. **Exact Remediation**

so that an agent can fix the violation without human help.

## 2. Architecture

### 2.1 Ban nuance-heavy primitives

Primitives that require nuanced judgment (for example raw `useEffect` in product components) are banned in product layers. Side effects MUST live in the Core SDK layer, which exposes declarative APIs.

### 2.2 Directory isolation

Code MUST be split into isolated layers (for example `core/`, `domain/`, `ui/`, or `main/` vs `renderer/`). CI MUST validate the dependency graph (dependency-cruiser or equivalent). Any cross-layer, reverse or circular dependency fails the build.

### 2.3 Zero comments and no escape hatches

- No justification comments (target: 99% reduction).
- No `setTimeout` to paper over race conditions.
- No unapproved `@ts-ignore` / `eslint-disable`.
- Any unavoidable suppression MUST carry an expiry date and a tracked ticket, both validated by CI.

## 3. Verification

### 3.1 Review artifacts, not diffs

PRs that touch user-facing flows or core state machines MUST attach at least one of:

- a UI / E2E recording (via CDP / headless browser),
- a visualized statechart,
- a performance benchmark diff.

### 3.2 Formal invariants

Core sync, distributed lock and financial state machines MUST have TLA+ specs or formal invariant checks. Foundational algorithms and high-frequency UI SHOULD use property-based testing.

## 4. Migration

### 4.1 Ratchet

- Teams MUST NOT do ground-up rewrites.
- Legacy debt is grandfathered into a baseline.
- New and modified files MUST be 100% compliant.
- Once an anti-pattern is eradicated, its rule is locked globally.

## Appendix: Merge gates for `main`

| Gate | Requirement |
|---|---|
| Gate 1: Architecture | Zero boundary violations |
| Gate 2: API hygiene | No banned primitives, no justification comments, no unauthorized type assertions |
| Gate 3: Artifacts | Required review artifacts attached |
| Gate 4: Invariants | Unit, property-based and formal checks pass |

## Enforcement map（本 repo 如何落實）

| 條文 | 落實方式 | 檢查 ID |
|---|---|---|
| §1.1 No prompt patching | `STATE.md` 的每條 Rules learned 都必須標註 `Check: <ID>`，且該 ID 存在於檢查器中 | `TEAM-005` |
| §1.2 Self-healing errors | 所有檢查器輸出都固定為 Rule ID / Root Cause / Remediation 三段 | 全部 |
| §2.1 Banned primitives | `.governance/config.json` 的 `banned_primitives`，預設禁止 `ui/`、`domain/` 使用 `useEffect` | `GOV-201` |
| §2.2 Directory isolation | 掃描 `src/` 的 import，依 `layers` 設定檢查方向，並偵測循環依賴 | `GOV-221`、`GOV-222` |
| §2.3 Escape hatches | 禁止未登記的 `@ts-ignore` / `@ts-expect-error` / `eslint-disable` / `setTimeout`，登記格式需含 `expires=YYYY-MM-DD ticket=XXX-123` 且未過期 | `GOV-231`、`GOV-232` |
| §2.3 Justification comments | 偵測 `// because`、`// HACK`、`// WORKAROUND` 等說明型註解 | `GOV-233` |
| §2.3 Type assertions | 禁止 `as any`、`as unknown as` | `GOV-234` |
| §3.1 Review artifacts | PR 觸及 `src/ui/` 或 `src/core/` 時，PR 內文必須含 `Artifact:` 連結 | `GOV-311` |
| §3.2 Formal invariants | 半自動：verifier 在 Gate 4 檢查；`.governance/config.json` 的 `invariant_paths` 內的檔案必須有對應測試 | `GOV-321` |
| §4.1 Ratchet | `.governance/baseline.json` 記錄既有違規；baseline 內的違規放行，但檔案一旦被修改就必須全清；baseline 只能變少 | `GOV-411`、`GOV-412` |
| Agent team 結構 | subagent 必須指定 model、verifier 不可有寫入工具、builder 必須隔離 | `TEAM-001`～`TEAM-004` |
