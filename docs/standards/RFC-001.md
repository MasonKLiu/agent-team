# RFC-001: AI-Native Engineering Governance Standards（務實精簡版）

* **Status:** Enforced
* **Scope:** All Autonomous Coding Agents, Scripts, and CI/CD Pipelines
* **Core Objective:** Every rule in this document is backed by an automated deterministic check—no hollow policies, no manual-only theater.

> **Keyword Definitions (per RFC 2119):**
> * **MUST / MUST NOT:** Absolute requirements enforced mechanically by scripts, hooks, or CI.

## 1. Determinism First

### 1.1 No Prompt Patching
* **MUST NOT:** Do not rely solely on appending prose instructions to `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, or `STATE.md` to fix recurring agent mistakes.
* **MUST:** When a failure occurs a second time (`REPEAT:` via `STATE.md`'s Failure log), codify it into a deterministic check (static rule, hook, linter rule, or unit test) and reference its exact ID via `Check: <RULE-ID>` in `STATE.md` (`TEAM-005`).

### 1.2 Self-Healing Error Messages
* **MUST:** Every automated check and hook block output must follow a three-part structured format so agents can self-correct without human translation:
  1. **Rule ID:** Unique identifier for the violated constraint.
  2. **Root Cause:** Concise explanation of why the pattern violates system invariants.
  3. **Exact Remediation:** Actionable fix or standard API replacement.

## 2. Architectural Boundaries & API Hygiene

### 2.1 Ban Nuance-Heavy Primitives Outside `core/`
* **MUST NOT:** Product layers (`ui/`, `domain/`) must not directly invoke error-prone low-level side-effect or timing primitives (`useEffect`, `useLayoutEffect`, `setTimeout`).
* **MUST:** Encapsulate side effects and timers in `src/core/`, exposing declarative APIs upward (`GOV-201`).

### 2.2 Physical Directory Isolation & Unidirectional Dependencies
* **MUST:** Enforce strict layered directories (`src/ui/` → `src/domain/` → `src/core/`) with zero reverse imports (`GOV-221`) and zero circular dependencies (`GOV-222`).

### 2.3 No Unregistered Escape Hatches, Workaround Comments, or Unsafe Casts
* **MUST NOT:** Do not silence the type checker or linter with unregistered `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, or `eslint-disable` (`GOV-231`/`GOV-232`), do not use unsafe casts like `as any` / `as unknown as` / `<any>` (`GOV-234`), and do not leave patch-excuse comments like `// HACK`, `// WORKAROUND`, `// because`, `// 暫時`, `// 繞過` (`GOV-233`).
* **MUST:** Any unavoidable suppression directive must carry an explicit expiration date and tracking ticket on the same line (`expires=YYYY-MM-DD ticket=ABC-123`) and be removed before expiry.

## 3. Legacy Codebase Evolution（Ratchet Principle）

### 3.1 Monotonic Technical Debt Ratchet
* **MUST:** Legacy violations may be grandfathered into `.governance/baseline.json` by a human (`ALLOW_BASELINE_WRITE=1`), tracked per `(rule_id, file)` occurrence count:
  * Untouched legacy files cannot increase their violation count.
  * Any newly created or modified file must comply 100% with RFC-001.
  * Paid-down debt must tighten the baseline (`GOV-411`); baseline counts can never grow (`GOV-412`).
  * Agents are mechanically blocked from altering `baseline.json` or running `--write-baseline` (`GUARD-005`, `SCOPE-002`).
